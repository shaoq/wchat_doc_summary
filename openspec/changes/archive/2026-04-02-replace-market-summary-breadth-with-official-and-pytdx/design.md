## Context

前一轮“完全免费优先”的宽度方案把 `mootdx` 作为成交额和涨跌统计的主源，但真实运行已经证明这条链路并不适合作为 `market-summary` 的稳定主路径。问题不只在单个 bug，而在方案本身：`mootdx` 提供的是证券列表 + 批量 quotes 的工具能力，不是面向 A 股宽度统计的稳定聚合接口；其底层 `tdxpy` 对证券类型的判定也会放大 universe 清洗问题，导致噪音日志、部分失真与频繁 partial。

这次设计要保留“免费优先”约束，但不再追求“单一免费源覆盖全部宽度数据”。对于 `market-summary` 这种盘后总结型命令，更合理的做法是按指标语义拆源：成交额使用交易所官方盘后统计，涨跌家数使用 `pytdx` 直接面向 A 股 universe 拉 quotes 并自行聚合。这样既能保持免费，又能把正确性和工程可控性拉回到可接受范围。

## Goals / Non-Goals

**Goals:**
- 将成交额改为使用上交所和深交所官方盘后成交概况，避免继续通过实时全市场快照间接推导两市成交额。
- 将涨跌统计改为使用 `pytdx` 直接拉取干净的 A 股 quotes，并基于 `price / last_close` 自行聚合。
- 保持现有 `FinanceClient -> MarketAnalyzer -> CLI/Cache` contract 和质量状态机制尽量不变。
- 将 `mootdx` 从宽度主路径中移除，避免继续把不稳定的证券列表 + 批量 quotes 方案当作主成功路径。

**Non-Goals:**
- 不在本次变更中重写指数、板块和涨停股的数据源策略。
- 不引入付费或积分门槛的数据源。
- 不实现历史交易日的官方成交额回补或任意历史宽度重建。
- 不调整 AI 模板和市场总结正文结构。

## Decisions

### 1. 成交额主源改为交易所官方盘后统计，而不是继续从实时 quotes 推导

成交额属于交易所天然会发布的盘后汇总指标，不需要再通过全市场股票行情逐只累加来近似推导。本次设计将：

- 上交所成交额从官方盘后成交概况解析
- 深交所成交额从官方盘后成交概况解析
- 最终在本地汇总为 `sh_volume / sz_volume / total_volume`

这样可以把成交额从“高请求量、高 partial 风险”的实时行情链路中剥离出来。

备选方案：
- 继续使用实时全市场快照累加成交额。放弃原因：免费源波动时最先失真，且对 `market-summary` 盘后场景并不必要。
- 直接使用 AKShare/东财的全市场成交额。放弃原因：仍然把正确性建立在第三方包装和单点接口上。

### 2. 涨跌统计主源改为 `pytdx`，并显式维护 A 股 universe

`pytdx` 相比 `mootdx` 更接近底层接口，控制面更清楚，适合在仓库内自己管理 universe 和聚合逻辑。本次要求：

- 通过 `pytdx` 获取沪深证券列表
- 仅保留明确的 A 股代码前缀：`00`、`30`、`60`、`68`
- 分批获取 quotes
- 使用 `price` 与 `last_close` 计算 `up_count / down_count / flat_count`

这样涨跌家数的正确性建立在“干净 universe + 可解释聚合”上，而不是封装层的隐式行为。

备选方案：
- 继续使用 `mootdx`。放弃原因：封装层副作用太多，且错误口径难以验证。
- 使用交易所官网直接解析涨跌家数。放弃原因：若无稳定官方聚合字段，页面结构更不利于长期维护。

### 3. 成交额与涨跌统计允许来自不同主源，但必须共享同一交易日语义

这一轮不再强求两项指标来自同一份底层样本。新的约束改为：

- 两项数据必须对应同一交易日
- 来源语义必须可追踪
- 若其中一项失败，不得把另一项成功结果抹掉

这比旧的“必须共享同一份快照”更符合指标本身的业务语义。

备选方案：
- 强制两项仍共用同一底层样本。放弃原因：成交额和涨跌家数的最优免费源本来就不同，硬绑在一起只会降低整体可用性。

### 4. 保留旧链路作为兜底，但不再把 `mootdx` 当兜底核心

旧宽度链路仍保留，以降低完全空值概率，但新的优先级是：

- 成交额：官方成交额 -> 旧宽度兜底
- 涨跌统计：`pytdx` -> 旧宽度兜底

`mootdx` 不再占据主路径，也不应继续占据主要兜底职责。

备选方案：
- 直接删除全部旧链路。放弃原因：回滚空间太小，且不利于短期稳定上线。

### 5. CLI 来源文案改为体现“官方成交额 + pytdx 统计”的组合成功

阶段 1 的宽度来源不能再只显示一个抽象来源名，而要让用户看得出：

- 成交额是否来自交易所官方
- 涨跌统计是否来自 `pytdx`
- 是否回退到旧链路
- 是否降级为空值

不要求把所有内部 adapter 名称暴露给用户，但要让输出能区分主源成功和兜底成功。

## Risks / Trade-offs

- [交易所官方页面结构可能变动] → 解析层做字段兜底和失败降级，不把 HTML 结构细节泄漏到 CLI。
- [`pytdx` 仍然依赖免费行情网络] → 通过干净 universe、分批请求和旧链路兜底降低失败概率。
- [成交额与涨跌统计不再共享同一底层样本] → 只要求共享同一交易日语义，并通过来源标签明确说明。
- [免费组合方案实现复杂度高于单一源] → 用指标拆源换稳定性，这是这次设计接受的复杂度成本。

## Migration Plan

1. 为项目引入 `pytdx` 依赖，并实现 A 股 universe 构建与 quotes 聚合逻辑。
2. 在 `FinanceClient` 中新增交易所官方成交额解析器，并将成交额主源切到官方统计。
3. 将涨跌统计主源切到 `pytdx`，保留旧链路兜底。
4. 调整 `breadth_quality` 与 CLI 来源展示，区分官方成交额、`pytdx`、兜底和空值降级。
5. 更新 contract、CLI 和缓存测试，确认盘后 `market-summary` 的宽度数据可以稳定通过主路径。

回滚策略：
- 若官方解析或 `pytdx` 主路径出现不可接受的不稳定，可快速恢复旧宽度主路径，同时保留新的来源语义和测试框架，避免再次误报成功。

## Open Questions

- 深交所官方成交概况最终采用页面解析、接口抓取还是现有封装库间接访问，哪种长期维护成本最低。
- `pytdx` quotes 批量大小和重试策略应如何配置，才能在盘后窗口兼顾速度与稳定性。
- 是否要在后续变更中将旧 `mootdx` 依赖彻底删除；本次不阻塞这一点。
