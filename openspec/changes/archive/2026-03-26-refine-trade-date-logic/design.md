# Design: 优化交易日判断逻辑

## Context
`market-summary` 命令用于生成 A 股市场总结。它需要确定"交易日"来获取对应的时间窗口数据（电报、文章）。
当前逻辑在交易日当天开市前（09:00 之前）执行时会返回空数据。

## Goals / Non-Goals
**Goals:**
- 在交易日当天开市前（09:00 之前）执行时，自动返回上一个已结束的交易日
- 保持现有行为不变：开市后（09:00 之后）执行时返回当天

**Non-Goals:**
- 不改变用户手动指定 `--date` 参数的行为
- 不修改时间窗口的计算逻辑（09:00-09:00 或 15:00-09:15)

## Decisions
**方案选择**: 在 `get_latest_trade_date()` 中增加时间判断逻辑
- 如果当前时间还没到 09:00，返回上一个交易日
- 否则返回当天（如果是交易日）
- **理由**: 保持向后兼容,只修改一个方法的行为

**备选方案**: 创建新方法 `get_effective_trade_date()`
- **理由**: 侵入性更小,但增加 API 复杂度
- **决定**: 选择方案 1，因为改动更集中,逻辑更清晰

## Risks / Trade-offs
| 风险 | 缓解措施 |
|-----|---------|
| 时区问题 | 使用本地时区(datetime.now())。与现有逻辑一致 |
| 节假日调休 | 使用 chinese_calendar 库判断。与现有逻辑一致 |
