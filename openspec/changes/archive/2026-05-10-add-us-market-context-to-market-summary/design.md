## Context

当前 `market-summary` 的主输入分为两组：

- `market_data`：A 股指数、成交额、涨跌统计、板块、涨停池
- `news_data`：财联社电报、财联社看盘、相关文章

CLI 在 [src/cli/ai.py](/Users/jie.hua/Documents/Developments/Projects/wchat_doc/src/cli/ai.py:682) 中编排三阶段执行，`AIProcessor.generate_market_summary()` 只接收上述输入。现有链路已经具备“交易日感知的文章/电报时间窗口”，但缺少结构化的海外市场信号，模型只能从零散新闻中间接推断隔夜美股影响，稳定性和可解释性都不足。

这次变更横跨行情采集、缓存、CLI 展示、AI prompt 和历史回放，属于明确的跨模块 contract 扩展。核心约束有两个：

- 海外市场信号必须绑定到“目标 A 股交易日”，但其抓取时间和行情时间通常发生在该交易日收盘后至下一交易日开盘前。
- 现有系统对历史交易日主要依赖缓存回放，因此新增的海外市场上下文也必须具备可缓存、可回放的标准化结构。

## Goals / Non-Goals

**Goals:**
- 为 `market-summary` 增加显式的海外市场上下文输入，优先覆盖美股三大指数、风险偏好指标和少量关键资产/龙头代理信号。
- 定义清晰的时间语义，区分 `target_a_trade_date`、`captured_at`、`as_of` 和 `session`。
- 让 CLI、缓存和 AI prompt 消费同一份标准化海外市场 contract。
- 保持在线、离线、历史回放三条路径的行为一致：在线可抓取，历史/离线优先读缓存。
- 在单一海外数据源降级时，允许总结继续生成，但必须明确暴露 `ok / partial / error` 状态。

**Non-Goals:**
- 不在本次设计中覆盖全球所有市场，只聚焦“对次交易日 A 股最有解释力”的海外上下文，默认以美股为核心。
- 不扩展为通用宏观终端或多市场行情产品，不追求完整资产覆盖与实时逐笔精度。
- 不要求第一期就引入海外新闻流全文抓取；重点先放在结构化盘面/风险指标。
- 不要求改变现有 A 股 `market_data` 主结构的语义边界。

## Decisions

### 1. 新增独立的 `global_market_context` 证据组，而不是塞进现有 `market_data` 或 `news_data`

设计选择：

- `MarketAnalyzer` 在现有 A 股市场数据之外，新增一个独立的海外市场上下文采集步骤。
- 最终用于 AI 的输入包显式包含 `global_market_context`，而不是把美股指标拼成文章文本或混入 A 股指数列表。

建议的标准化结构：

```json
{
  "global_market_context": {
    "status": "ok|partial|error",
    "target_a_trade_date": "2026-05-07",
    "captured_at": "2026-05-07T22:45:00+08:00",
    "us_market": {
      "status": "ok|partial|error",
      "session": "pre_market|regular|post_market|closed",
      "as_of": "2026-05-07T22:44:00+08:00",
      "indices": [
        {"symbol": "DJIA", "name": "道琼斯工业平均指数", "price": 0, "change_pct": 0},
        {"symbol": "SPX", "name": "标普500", "price": 0, "change_pct": 0},
        {"symbol": "IXIC", "name": "纳斯达克综合指数", "price": 0, "change_pct": 0}
      ],
      "risk_signals": {
        "vix": {"value": 0, "change_pct": 0},
        "dxy": {"value": 0, "change_pct": 0},
        "us10y": {"value": 0, "change_bp": 0}
      },
      "leaders": [
        {"symbol": "NVDA", "name": "NVIDIA", "change_pct": 0}
      ],
      "source": "..."
    }
  }
}
```

理由：

- 这部分信息语义上既不是 A 股盘面，也不是新闻正文，而是“次交易日定价背景”。
- 独立证据组更利于 CLI 展示、prompt 组织和后续扩展到港股/大宗商品。

备选方案：

- 放进 `market_data`。放弃原因：会模糊 A 股盘面与隔夜海外上下文的边界。
- 放进 `news_data`。放弃原因：结构化行情会退化成文本附件，难以稳定消费。

### 2. 用“目标交易日绑定 + 抓取时间独立记录”的双时间模型

设计选择：

- 海外上下文记录必须同时保存：
  - `target_a_trade_date`：这份上下文服务于哪个 A 股交易日总结
  - `captured_at`：系统何时抓取到这份数据
  - `as_of`：上游行情本身的时间
  - `session`：美股交易阶段

理由：

- `market-summary` 的核心主键仍然是 A 股交易日，但美股数据往往属于该交易日夜间或次日清晨。
- 如果只存 `trade_date`，后续历史回放将无法区分“盘后初版总结”与“次日盘前再生成”的上下文差异。

备选方案：

- 把海外市场数据也按 `trade_date` 直接缓存。放弃原因：语义不完整，无法描述实际抓取时刻和交易阶段。

### 3. 在线模式只抓“少而硬”的海外指标，优先保证稳定性与解释力

第一期纳入的字段建议固定为：

- 三大指数：`DJIA`、`SPX`、`IXIC`
- 风险偏好：`VIX`
- 宏观约束：`DXY`、`US10Y`
- 行业/龙头代理：`SOX` 或 `NDX` 二选一，外加最多 3 到 5 只高权重科技股

理由：

- 这些指标足以覆盖“风险偏好、成长风格、利率约束、科技权重”的主导传导路径。
- 指标越多，退化与脏数据概率越高，也会放大 prompt 噪音。

备选方案：

- 直接抓更完整的美股股票池或大量 ETF。放弃原因：实现复杂度与 prompt 成本过高，第一期收益不成比例。

### 4. CLI 第 1 阶段展示海外上下文状态，但不改变现有三阶段主结构

设计选择：

- 保持现有三阶段：
  - 获取市场数据
  - 获取新闻数据
  - 生成并保存市场总结
- 将海外市场上下文作为“阶段 1 的附加状态块”展示，包括：
  - 来源状态
  - `session`
  - `as_of`
  - 关键指数摘要

理由：

- 海外市场上下文更接近“用于总结的市场证据”，不应新开一个独立大阶段。
- 保持 CLI 稳定结构，降低认知和测试改动面。

备选方案：

- 新增第 4 阶段“获取海外市场数据”。放弃原因：流程收益有限，会破坏既有阶段契约。

### 5. 历史交易日与离线路径一律优先消费缓存，不对过去日期做临时在线补抓

设计选择：

- 当前交易日在线模式：允许采集并保存海外上下文。
- 历史交易日：若缓存存在则回放；若不存在则标记缺失，不承诺在线回补历史海外快照。
- `--offline`：只消费本地缓存中的海外上下文，不触发网络请求。

理由：

- 海外市场数据本身具有强时间敏感性，历史补抓很难精确还原当时生成总结看到的状态。
- 与现有 `market-summary` 的历史数据策略一致，易于解释。

备选方案：

- 对历史交易日在线回补海外市场数据。放弃原因：会制造伪历史，破坏总结可追溯性。

### 6. AI prompt 使用单独占位段落，并显式约束“没有海外数据时不得臆测”

设计选择：

- `AIProcessor.generate_market_summary()` 新增 `global_market_context` 参数。
- 模板中新增一个海外市场上下文段落，仅在有数据时提供结构化摘要。
- 若状态为 `partial` 或 `error`，prompt 必须明确提示模型“仅可基于已给信号，不得补全未知海外走势”。

理由：

- 当前市场总结已经在做结构化证据分组，新增一段最符合现有生成策略。
- 必须限制模型在无数据时用常识臆测隔夜美股。

备选方案：

- 由 `MarketAnalyzer` 直接生成自然语言段落交给模板。放弃原因：会把数据层和表达层耦合起来。

## Risks / Trade-offs

- [海外行情源不稳定或字段漂移] → 采用小字段集和标准化质量状态，必要时允许 `partial` 继续生成总结
- [双时间模型增加缓存与展示复杂度] → 固定字段命名，并在 CLI 中始终打印 `session/as_of`，减少误读
- [历史回放缺少海外上下文时，历史总结信息不完整] → 明确将其暴露为缺失状态，而不是尝试伪造历史快照
- [海外指标过多导致 prompt 噪音上升] → 第一阶段严格限制指标数量，只保留解释力最高的信号
- [不同数据源时间戳时区不一致] → 在标准化层统一转换为带时区的上海时间展示，同时保留原始语义字段

## Migration Plan

1. 定义 `global_market_context` 的标准化 contract 和状态枚举。
2. 在市场分析服务中接入在线采集与缓存读取编排。
3. 扩展缓存层保存/读取与目标 A 股交易日绑定的海外上下文。
4. 更新 CLI 阶段 1 摘要与 `AIProcessor`/模板输入。
5. 补齐在线、历史、离线、失败退化、时间语义相关测试。

回滚策略：

- 若海外上下文采集链路不稳定，可先回退到“不采集海外上下文但保留其他 `market-summary` 能力”的状态。
- 若缓存结构改造引发问题，可暂时禁用海外上下文缓存写入，仅保留在线非持久化路径进行隔离排查。

## Open Questions

- 第一版 `leaders` 是否默认固定为美股科技龙头，还是根据当日主题在少数候选池中动态选择；实现阶段需要在稳定性与相关性之间取舍。
- `SOX` 与 `NDX` 哪个更适合作为半导体/成长风格代理，是否需要两者并存；需要结合现有数据源可得性确认。
- 是否需要把港股或中概股指数纳入第一期上下文；从需求价值看不是必须，但实现阶段可能会被提出作为扩展项。
