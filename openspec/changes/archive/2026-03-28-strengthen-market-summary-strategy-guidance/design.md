## Context

当前 `market-summary` 的核心问题已经不在“能不能生成总结”，而在“生成出来的总结是否稳定、可信、可复盘”。现状里有几个明显缺口：

- 模板对“后续策略建议”的约束太弱，导致该内容有时单独成段，有时混在别的章节里，有时直接缺失。
- 模型被要求输出板块、龙头、连板与策略建议，但输入给它的事实仍偏原始拼接，关键字段缺乏显式组织，容易诱发脑补和泛化表述。
- 当行情或题材证据不足时，当前模板没有明确的降级约束，因此模型仍可能输出方向性较强的建议。
- 现有测试主要覆盖 CLI 流程，对市场总结正文结构和策略建议的质量边界几乎没有回归保护。

这次变更跨越模板、AI prompt 组织和测试约束三个层面，适合先把设计决策固定下来，再进入实现。

## Goals / Non-Goals

**Goals:**
- 让市场总结稳定输出“明日观察”和“后续策略建议 / 风险提示”等固定章节。
- 让策略建议明确绑定证据来源，减少空泛的主观判断。
- 明确数据不足时的降级语义，避免在弱证据输入下给出强结论。
- 为市场总结正文结构增加可回归的测试边界。

**Non-Goals:**
- 不重构 `market-summary` 的整个数据采集链路。
- 不引入新的外部模型服务、向量检索或多阶段 agent 流程。
- 不追求生成内容“绝对正确”，本次目标是先把结构稳定性和证据约束收紧。

## Decisions

### 1. 用“固定章节合同”收紧模板，而不是只补一句“请给出策略建议”

模板会从当前偏开放式的大段说明，收紧为固定章节合同，至少包含：
- 市场概览
- 主线与轮动
- 个股与情绪
- 关键信息催化
- 明日观察清单
- 后续策略建议与风险提示

这样做的原因是：真正漂移的不是某一两句文案，而是整体输出骨架没有被固定。只有把章节层级收紧，后续“策略建议”才能稳定存在并可测试。

备选方案：继续保留原模板，只补充一句“最后增加策略建议”。
拒绝原因：约束太弱，无法解决章节缺失和位置漂移。

### 2. 仍使用单次 LLM 生成，但先把输入组织成更明确的证据块

不引入第二次 LLM 调用来单独生成策略建议，而是在现有 `generate_market_summary()` 路径里，把输入组织为更清晰的事实块，例如：
- 行情总览
- 强弱板块
- 涨停 / 高标线索
- 财联社电报关键催化
- 看盘中的盘中轮动线索
- 文章中的观点补充
- 数据缺口提示

这样能在不增加时延和成本的前提下，提高单次生成的稳定性。

备选方案：先让模型生成正文，再做第二次“策略总结”提炼。
拒绝原因：成本、时延和测试面都会扩大，而且第二次调用仍会继承第一次输出中的幻觉。

### 3. 策略建议必须采用“证据 + 应对 + 风险”格式，而不是自由散文

每条策略建议应至少回答三件事：
- 为什么值得关注：对应的行情 / 新闻 / 个股证据
- 该如何观察或应对：偏观察清单、触发条件、仓位或节奏描述
- 何时失效或需要回避：主要风险与反证

这能把“建议”从泛泛的观点，收紧成可复盘的判断框架。

备选方案：让模型自由发挥策略建议段落。
拒绝原因：最容易再次出现“大主线、强逻辑、建议关注”这种高概括低约束文本。

### 4. 数据不足时切换到“观察模式”，禁止强方向性结论

当关键字段缺失，例如指数、成交额、板块、涨停链条或核心新闻证据明显不足时，模板和 prompt 应共同要求模型降级输出：
- 明确指出哪些数据不足
- 只输出观察项与风险提示
- 不输出“重点布局”“主线明确”这类强表达

备选方案：由代码直接阻止生成。
拒绝原因：很多场景并非“完全不能生成”，而是“可以生成低置信度总结”；完全阻断会损失可用性。

### 5. 增加针对 summary 结构的测试钩子，而不仅是 CLI 流程测试

实现时应增加针对模板 / prompt 输出约束的测试，至少覆盖：
- 正常输入下包含固定章节
- 数据不足时进入观察模式
- 策略建议必须包含风险提示或失效条件语义

不要求逐字锁死整段生成文本，但要锁住章节存在性和关键约束。

## Risks / Trade-offs

- [模板约束过强导致文风变僵] -> 固定章节与关键字段约束，正文表达仍保留自然语言空间。
- [单次 LLM 生成仍可能有少量脑补] -> 通过显式证据块、数据缺口提示和降级模式降低风险，而不是假设完全消除。
- [内容测试容易脆弱] -> 只断言章节结构、关键提示词和降级行为，不锁死整篇文案。

## Migration Plan

无需数据迁移。实现时更新市场总结模板、调整 `AIProcessor.generate_market_summary()` 的 prompt 组织方式，并补充对应测试后即可上线。
