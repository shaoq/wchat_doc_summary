## Why

当前 `sector-trends` 已经能够发现和跟踪细颗粒度板块，但用户在实际复盘时还需要按“主线/产业链/主题”归拢观察，例如把机器人、减速器、传感器、机器视觉等细分方向放入“人形机器人”主题下判断共振、扩散和退潮。

直接合并细分板块会损失独立行情和独立证据，因此需要在现有细颗粒度板块之上新增一层可确认、可建议、可跟踪的分组映射。

## What Changes

- 新增板块分组能力，用于维护主题组、分组成员和成员关系类型。
- 支持查看分组列表、分组详情、组内细分板块和成员状态。
- 支持系统生成分组建议，包括新建分组、向已有分组补充成员、调整成员关系类型。
- 支持建议的接受、部分接受、忽略和去重，避免重复提示同一组成员关系。
- 支持基于已确认成员生成组级趋势跟踪报告，分析组内共振、扩散、轮动、核心/补涨结构和退潮信号。
- 组级跟踪默认先补齐已跟踪成员当天缺失的单板块分析，再生成分组总结，避免组级判断依赖过期成员结论。
- 支持显式跳过成员刷新，允许在成本或耗时敏感场景下使用已有成员总结和原始证据生成分组报告。
- 优化板块和分组总结命令的终端输出，参考 `market-summary` 的阶段式反馈展示执行进度、阶段结论、成员刷新情况和最终产物路径。
- 总结生成命令完成后默认不输出报告正文，只输出报告文件路径、关键标签、耗时和批处理统计；正文查看由 `show` / `history` 等查看命令承担。
- 保留现有细分板块 `candidate` / `tracked` / `inactive` / `ignored` 生命周期，不降低现有板块颗粒度。

## Capabilities

### New Capabilities
- `sector-group-tracking`: 板块分组、分组建议、成员确认映射和组级趋势跟踪。

### Modified Capabilities
- None.

## Impact

- Affected code:
  - `src/models/schema.py`: 新增分组、成员映射、建议和组级总结模型。
  - `src/storage/database.py`: 新增表初始化和索引/唯一约束。
  - `src/services/sector_trend_service.py` 或新增服务模块：分组 CRUD、建议生成、建议接受、组级证据收集和组级更新。
  - `src/cli/sector_trends.py`: 新增 `groups` 子命令组。
  - `src/services/ai_processor.py` 和模板目录：新增组级趋势总结 prompt。
  - `tests/`: 增加模型、服务、CLI 和组级更新测试。
- Data model impact:
  - 新增表，不迁移或合并现有 `tracked_sectors` 记录。
  - 正式分组成员通过多对多映射指向现有细分板块。
- Behavior impact:
  - 现有 `sector-trends discover/ls/init/update/show/history` 行为保持不变。
  - 新增组级命令默认只读取已确认映射，不静默扩大跟踪池。
  - 组级更新会默认触发已跟踪成员的缺失单板块分析；用户可通过显式参数跳过刷新。
  - 板块和分组总结生成命令的终端输出将从正文预览改为阶段进度和产物路径展示。
