# 财联社电报 API 技术设计

## Context

### 当前状态

现有系统使用以下数据源获取财经数据：
- 腾讯财经 - 指数数据
- 东方财富/akshare - A股票列表、板块数据

但缺乏实时财经新闻快讯能力。

### 约束

- 遵循现有 API 客户端架构（FinanceClient 模式）
- 使用 curl 命令绕过 Python HTTP 库问题（参考 EastMoneyCurlClient）
- 支持缓存机制
- 异步请求支持

## Goals / Non-Goals

**Goals:**
- 集成财联社电报 API 获取实时财经快讯
- 提供可配置的请求参数（主题、数量、时间范围）
- 实现缓存减少重复请求
- 支持关键词过滤快讯

**Non-Goals:**
- 实现财联社完整 API（仅限电报接口)
- 实时推送功能（仅拉取模式）
- 付费 API 功能（仅免费接口)

## Decisions

### 1. API 客户端架构

**决定**: 创建独立的 `ClsTelegraphClient` 类，遵循现有客户端模式。

**理由**:
- 与 EastMoneyCurlClient、TencentFinanceClient 保持一致
- 使用 curl 命令避免 Python HTTP 库问题
- 独立类便于测试和维护

### 2. 数据模型

**决定**: 使用简单的字典格式返回快讯数据。

```python
{
    "title": "快讯标题",
    "content": "快讯内容",
    "publish_time": "发布时间",
    "topics": ["关键词1", "关键词2"],  # 相关主题标签
    "importance": 1  # 重要程度 1-3
}
```

**理由**: 轻量级，易于扩展，与现有数据格式一致。

### 3. 缓存策略

**决定**: 使用内存缓存，TTL 5 分钟。

**理由**:
- 快讯更新频率较高（每分钟)
- 减少对财联社服务器的请求压力
- 5 分钟 TTL 平衡时效性和数据新鲜度

### 4. 错误处理

**决定**: 静默失败，返回空列表，记录警告日志。

**理由**:
- 快讯是辅助功能，失败不应影响主流程
- 与现有 FinanceClient 错误处理策略一致

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| API 不可用 | 无法获取快讯 | 多数据源备份（akshare） |
| 请求频率限制 | IP 被封禁 | 遵守 rate limit，使用缓存 |
| 数据格式变化 | 解析失败 | 增加数据验证，版本兼容处理 |
