## Context

当前系统已具备：
- 微信公众号文章抓取和存储能力
- AI 处理服务（基于 Anthropic API）
- CLI 命令框架（Click + Rich）

需要新增：
- A 股交易日判断（排除周末 + 节假日）
- 财经行情数据获取
- 市场总结生成与存储

## Goals / Non-Goals

**Goals:**
- 实现智能交易日判断（支持周末和中国法定节假日）
- 整合多数据源生成市场总结（已抓取文章 + 网络行情）
- 提供可编辑的总结模板
- 保存历史总结到数据库和文件

**Non-Goals:**
- 不实现实时行情推送（仅日终总结）
- 不支持个股深度分析（仅市场概览）
- 不实现自动交易或投资建议

## Decisions

### 1. 交易日判断方案

**决定**: 使用 `chinese-calendar` 库

**理由**:
- 内置完整的中国节假日数据
- 离线运行，无需外部 API
- 活跃维护，每年更新

**备选方案**:
- 交易所日历 API：需要网络，可能不稳定
- 手动维护日历表：维护成本高

### 2. 财经数据来源

**决定**: 使用 `akshare` 开源库

**理由**:
- 开源免费，无 API 限制
- 数据全面（指数、板块、个股）
- 社区活跃，文档完善

**备选方案**:
- 东方财富 API：需要注册，有调用限制
- 新浪财经 API：非官方，稳定性存疑

### 3. 模板存储位置

**决定**: 项目根目录 `templates/` 文件夹

**理由**:
- 用户易于查找和编辑
- 与代码分离，更新不影响功能
- 可扩展（未来可添加更多模板）

### 4. 输出存储方案

**决定**: 数据库 + Markdown 文件双存储

**理由**:
- 数据库：便于查询和程序化访问
- 文件：便于阅读、分享和版本控制

### 5. 命令设计

```bash
wchat ai market-summary              # 自动总结最近交易日
wchat ai market-summary --date YYYY-MM-DD  # 指定日期
wchat ai market-summary --offline    # 仅使用已抓取文章
wchat ai market-summary --list       # 查看历史总结
```

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| `akshare` 数据源不稳定 | 添加重试机制和错误处理，支持 `--offline` 模式 |
| 节假日数据过期 | `chinese-calendar` 每年更新，提醒用户升级依赖 |
| AI 生成内容不准确 | 明确提示词，结构化输出，用户可编辑模板 |
| 网络请求超时 | 设置合理超时时间，提供进度提示 |
