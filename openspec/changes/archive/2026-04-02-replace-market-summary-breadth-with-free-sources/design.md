## Context

当前 `market-summary` 的失败热点并不平均分布在所有市场数据类型上。指数链路已经有腾讯专用适配器，板块和涨停股虽然仍会偶发抖动，但它们并不是导致阶段 1 频繁失真的主因；真正长期不稳定的是成交额和涨跌统计，因为这两项共享东方财富全市场快照及其备用链路。

本次目标明确为“完全免费优先”，因此设计重点不是把全部市场数据统一迁移到一个新提供方，而是优先替换最脆弱、最关键的宽度数据主链路。与此同时，仓库已经围绕统一 contract、宽度质量状态和缓存门控做过一轮治理，所以新的方案必须尽量复用现有 `FinanceClient -> MarketAnalyzer -> cache/CLI` 结构，避免再次扩散改动面。

## Goals / Non-Goals

**Goals:**
- 为成交额和涨跌统计引入免费优先的新主源，并避免继续把东方财富快照当作唯一主路径。
- 保持成交额和涨跌统计继续共享同一轮全市场样本，确保两个指标来自同一抓取时刻。
- 保持现有统一 contract、宽度质量状态和缓存门控机制可继续复用。
- 将改动收敛在 `FinanceClient` 及其调用边界，不重写 `market-summary` 主流程。

**Non-Goals:**
- 不在本次变更中重写板块和涨停股的数据源策略。
- 不引入付费或积分门槛数据源。
- 不实现历史交易日的免费全市场重建。
- 不修改 AI 总结模板和市场总结正文结构。

## Decisions

### 1. 为宽度数据新增 `mootdx` 主适配器，而不是整体替换 `FinanceClient`

实现上新增一个专门服务于“成交额 + 涨跌统计”的 `mootdx` 宽度适配器，由它提供同一轮全市场行情样本，再在本地聚合出：

- `volume`
- `statistics`

这样可以直接替换当前最脆弱的共享快照链路，同时不影响指数、板块、涨停股的既有适配器。

备选方案：
- 全量切换到 `mootdx`，包括指数、板块、涨停股。放弃原因：改动面过大，而且板块、涨停股当前已有可用免费链路。
- 新建一个完全独立的 `FreeMarketDataClient` 替代 `FinanceClient`。放弃原因：会打散现有 contract、测试和缓存门控结构。

### 2. 宽度数据继续采用“单样本双指标”设计

无论主源还是兜底源，成交额和涨跌统计都必须继续复用同一轮样本，不能拆成两个独立请求。具体要求是：

- `mootdx` 成功时，用同一批行情样本同时计算两项结果
- `mootdx` 失败时，再回退到现有旧链路，并继续保持共享样本语义
- 若所有链路都失败，返回现有零值 contract，并保留 `breadth_quality=error`

备选方案：
- 分别为成交额和涨跌统计调用不同免费源。放弃原因：会破坏两项数据的一致性，也会增加抓取次数和排障复杂度。

### 3. 现有旧链路保留为次级兜底，而不是立即删除

“免费优先”不等于“必须彻底移除所有现有免费源实现”。本次将现有东财/AKShare 宽度链路从主路径降为次级兜底，理由是：

- 它们已经与当前 contract 和测试体系对齐
- 在 `mootdx` 个别交易时段不可用时，保留次级兜底能减少完全空值的概率
- 用户当前最关心的是摆脱东财单点依赖，而不是一次性清除所有旧实现

备选方案：
- 彻底移除旧宽度链路。放弃原因：实施风险更高，且不利于短期稳定性回归。

### 4. CLI 来源语义改为体现“宽度主源”与“降级结果”

现有 stage 1 已支持逐项状态展示，但来源标签仍然偏聚合视角。本次要求 CLI 能够体现：

- 宽度数据命中免费主源
- 宽度数据回退到旧免费兜底链路
- 宽度数据最终降级为空值

不要求在本次把所有来源逐项打印成完整矩阵，但至少要让用户看得出“这次宽度数据是否仍在走免费主主链路”。

备选方案：
- 仅通过日志体现主源与降级路径。放弃原因：用户实际感知发生在 CLI 阶段 1，而不是日志文件。

## Risks / Trade-offs

- [新增 `mootdx` 依赖可能带来环境兼容问题] → 通过依赖安装说明、适配器隔离和 contract 测试降低风险。
- [不同免费源之间口径存在轻微差异] → 保持统一归一化 contract，并把验收重点放在结构和量级正确，而不是逐笔完全一致。
- [保留旧兜底链路会增加实现复杂度] → 仅把旧链路保留在宽度降级路径，不扩展到其它数据类型。
- [`mootdx` 对板块和涨停股支持不足] → 明确这些项不在本次迁移范围，避免免费优先目标无限扩张。

## Migration Plan

1. 为项目引入 `mootdx` 依赖，并在 `FinanceClient` 中增加宽度样本适配器。
2. 将成交额和涨跌统计主路径改为 `mootdx`，保留旧宽度链路作为次级兜底。
3. 更新宽度质量状态中的来源标识，使 CLI 能区分主源成功、兜底成功和失败降级。
4. 更新 CLI 状态和来源展示，但保持现有输出结构与缓存 contract 不变。
5. 补充 contract、CLI 和缓存回归测试，确认 `market-summary` 在免费优先路径下稳定。

回滚策略：
- 若 `mootdx` 适配器在真实环境中表现不稳定，可通过恢复旧宽度主路径并保留新测试与来源语义代码的方式快速回滚，而无需回退整个市场总结流程。

## Open Questions

- `mootdx` 适配器最终应直接读取“全市场快照”，还是先限定沪深 A 股范围后再统一聚合。
- 宽度来源标签是否需要细分到 `primary / fallback / empty` 三档，还是继续沿用现有 `breadth_quality.source` 语义即可。
- 是否要在后续变更中继续把板块与涨停股也迁移到“更少依赖东财包装”的免费方案；本次不阻塞这个后续方向。
